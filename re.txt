Beginner-friendly • practical • submission-focused
 
1. Understand the task before writing code
The assessment asks for only the Garibook homepage. The evaluator is explicitly looking at visual accuracy, responsive behavior, React component structure, interactions, GSAP usage, code quality, and your ability to explain what you built.
Do not overbuild: You do not need to reproduce the entire Garibook product, backend, authentication, booking engine, or other pages. Focus your time on the homepage UI and the important interactions visible there.

Non-negotiable requirements
☐ Use React.js and JavaScript.
☐ Make the homepage responsive on desktop, tablet, and mobile.
☐ Use multiple reusable components; do not put the full homepage in one component.
☐ Implement important visible interactions where practical.
☐ Use GSAP for at least 2 meaningful animations.
☐ Add hover, focus, and interaction states.
☐ Keep the code clean, readable, and organized.
☐ GitHub repository must be accessible and contain a README with setup/run instructions.
☐ Submit a maximum 2-minute screen recording.
☐ Test desktop and mobile before submission.
☐ Submit through the provided Google Form.
What “production-quality” should mean here
Area	Good submission behavior
Visual	Spacing, typography, sizing, colors, borders, radius, alignment and section rhythm are close to the reference.
Responsive	Layout adapts cleanly instead of only shrinking; no horizontal scroll or overlapping content.
React	Sections are broken into logical reusable components; repeated cards are data-driven where sensible.
Interactions	Menus, tabs/toggles, buttons, form controls, hover/focus states and relevant UI changes feel intentional.
Motion	GSAP animations support the page instead of distracting from it.
Code	Clear file names, predictable folders, no dead code, no secrets, no node_modules committed.

7. Build the hero and booking panel first
This is usually the highest-impact area because it is visible immediately. Match its height, content alignment, imagery, and booking panel carefully.
Booking form implementation
•	Use real form controls where practical: select, input, button, radio/toggle controls.
•	Use labels even if the visual design hides them; accessibility matters.
•	Mirror visible trip-type options such as One Way / Round Way / Hourly if they are present on the reference.
•	Add focus-visible styles so keyboard users can see the active control.
•	The Continue button does not need a real booking backend unless the reference interaction can be represented safely with frontend state.
const [tripType, setTripType] = useState("one-way");

<button
  type="button"
  className={tripType === "one-way" ? "trip active" : "trip"}
  onClick={() => setTripType("one-way")}
>
  One Way
</button>

Frontend-only behavior is acceptable: For this assessment, demonstrate state changes and interactions without inventing a backend. If Continue cannot complete a real booking, validate the visible fields or show a small UI response instead of pretending a server action exists.

8. Build repeated cards from data
Avoid copy-pasting the same JSX four times. Put repeated content into an array.
export const services = [
  {
    title: "Intercity Car Rental",
    description: "Travel between cities with comfort and confidence.",
    icon: "/assets/service-intercity.svg",
  },
  // Add the remaining items from the reference.
];

<div className="services-grid">
  {services.map((service) => (
    <ServiceCard key={service.title} {...service} />
  ))}
</div>

This makes the UI easier to maintain and demonstrates the reusable React thinking the assessment asks for.
9. Make responsiveness intentional
Do not wait until the end to discover that the page only works at one width. Complete each major section on desktop, then immediately test tablet and mobile.
Width	What to check
≥ 1200 px	Full desktop composition, maximum content width, multi-column layouts.
~1024 px	Navigation space, hero proportions, card grids, promotional sections.
~768 px	Tablet stacking, 2-column → 1/2-column transitions, readable spacing.
430/390/375 px	Mobile menu, single-column content, form controls, no overflow.

Recommended responsive techniques
•	Use CSS Grid or Flexbox, not absolute positioning for the whole page.
•	Use clamp() for headings when useful.
•	Stack image/text promotional sections on narrow screens.
•	Reduce section padding on mobile.
•	Make form fields full width on mobile.
•	Give tap targets enough size; avoid tiny icon-only controls.
•	Check that images preserve aspect ratio and do not cause horizontal scrolling.
@media (max-width: 768px) {
  :root {
    --page-pad: 16px;
    --section-space: 64px;
  }

  .desktop-nav { display: none; }
  .mobile-menu-button { display: inline-flex; }

  .hero-grid,
  .promo-grid {
    grid-template-columns: 1fr;
  }
}

10. Add at least 2 meaningful GSAP animations
Use motion to improve hierarchy. Do not animate everything.
Animation 1 — hero entrance
import { useLayoutEffect, useRef } from "react";
import gsap from "gsap";

function Hero() {
  const root = useRef(null);

  useLayoutEffect(() => {
    const ctx = gsap.context(() => {
      gsap.from(".hero-reveal", {
        y: 28,
        opacity: 0,
        duration: 0.8,
        stagger: 0.12,
        ease: "power3.out",
      });
    }, root);

    return () => ctx.revert();
  }, []);

  return <section ref={root}>{/* ... */}</section>;
}

Animation 2 — scroll reveal for cards/sections
Install/use ScrollTrigger if you choose a scroll-triggered effect.
import gsap from "gsap";
import { ScrollTrigger } from "gsap/ScrollTrigger";

gsap.registerPlugin(ScrollTrigger);

gsap.from(".service-card", {
  scrollTrigger: {
    trigger: ".services-grid",
    start: "top 80%",
  },
  y: 30,
  opacity: 0,
  duration: 0.6,
  stagger: 0.1,
  ease: "power2.out",
});

Meaningful means: The animation helps reveal the hero, guides attention, or introduces a group of cards/sections. A random spinning logo or decorative movement that does not support the interface is weaker evidence.

Respect reduced motion
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    scroll-behavior: auto !important;
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
  }
}

11. Add visible interaction states
☐ Navigation links: hover + focus-visible.
☐ Buttons: hover, active/pressed, focus-visible.
☐ Cards: subtle hover only if the reference suggests interactivity.
☐ Inputs/selects: focus border/ring and useful placeholder text.
☐ Mobile menu: open/close state and Escape key if implemented.
☐ Clickable images/icons: accessible name if they act as controls.
☐ Use semantic section/headings; keep heading order logical.
☐ Provide alt text for informative images; decorative images can use empty alt text.

20. Safe and useful way to use AI tools
The assessment allows AI tools, but you must understand the code and explain it. Use AI as a pair programmer rather than asking it to generate an opaque project you cannot debug.
Good AI requests
•	“Here is my Header component and CSS. At 768px the nav overlaps the logo. Fix the responsive CSS without changing the desktop design.”

•	“Add a GSAP scroll reveal to these cards using gsap.context and cleanup correctly.”

Avoid this workflow
•	Generating the entire project in one prompt, pasting it blindly, and being unable to explain the architecture or GSAP code.
21. Quick troubleshooting
Problem	Fix
Blank page	Check browser console; verify imports/exports and JSX syntax.
Image missing after deploy	Use correct public or imported asset paths; avoid local file-system paths.
GSAP runs twice in development	Use gsap.context cleanup; remember React Strict Mode may expose side effects during development.
ScrollTrigger not working	Import ScrollTrigger, register it once, and ensure the target/trigger exists.
Horizontal scroll on mobile	Inspect wide fixed-width elements, transforms, images and padding; use overflow debugging only temporarily.
Mobile menu behind content	Check position, stacking context and z-index.
Vercel build fails	Run npm run build locally first; fix build errors before redeploying.
Layout differs from reference	Re-check container width, typography, spacing, image aspect ratio and section order before tiny details.
